# mapping.json / screens.json 레퍼런스

## mapping.json

양식 해석 결과. 같은 양식을 다시 처리할 때 분석 단계를 건너뛰게 해준다.

### excel

| 필드 | 값 | 설명 |
|---|---|---|
| `layout` | `sheet-per-screen` \| `table` | 1시트=1화면인지, 1행=1화면인지 |
| `sheet_include` | 정규식 | `sheet-per-screen`에서 화면 시트만 고르는 필터. 예: `^설계_` |
| `screen_meta.cell` | 셀 주소 | 화면ID·화면명이 든 셀. 예: `A1` |
| `screen_meta.pattern` | 정규식 | 명명 그룹 `id`, `name`으로 분리. 안 맞으면 시트명이 ID가 된다 |
| `sheet` | 시트명 | `table` 레이아웃에서 화면 목록이 있는 시트 |
| `header_row` | 정수 | `table` 레이아웃의 헤더 행 번호 |
| `columns` | `{"id": "A", "name": "B"}` | `table` 레이아웃의 화면ID·화면명 열 |
| `fields` | `{"설명": "C"}` | `table` 레이아웃의 화면 단위 부가 값. 키는 자유 |
| `detail.header_scan_column` | 열 문자 | 상세 헤더를 찾을 열. 예: `A` |
| `detail.header_marker` | 문자열 | 헤더 행을 식별하는 값. 예: `No.` |
| `detail.mode` | `grouped-rows` \| `merged-cells` \| `none` | `table` 레이아웃 전용. 화면ID가 빈 행을 직전 화면 상세로 귀속. 앞의 두 값은 동작이 같다 |
| `detail.columns` | `{"no": "A", "desc": "D"}` | 상세 열 매핑. 키는 자유이나 `no`는 표 번호 칸에 쓰인다 |
| `cover.sheet` | 시트명 | 표지 시트를 명시 지정(그 이름의 시트가 없으면 표지 없음 처리). 생략하면 아래 자동 판별 규칙을 따른다 |
| `meta_overrides` | `{"프로젝트명": "값"}` | 표지 인식 결과를 사람이 덮어쓴다 |

**표지 시트 자동 판별 (`cover.sheet` 생략 시, `find_cover_sheet`):**

1. 시트 이름에 `표지`·`표제`·`개요`·`cover`·`front`가 들어가면 **위치와 무관하게** 그 시트를 표지로 쓴다. 이 단계가 아래 "첫 시트" 폴백보다 먼저 검사된다.
2. 그런 이름이 없으면 화면 시트가 아닌 첫 시트(`sheet_include`가 없으면 그냥 첫 시트)를 후보로 삼되, 그 시트에서 라벨-값 쌍이 **2개 이상** 나올 때만 표지로 채택한다. 못 미치면 표지 없음으로 처리해 `meta`가 비고, `extract.py`가 안내 문구를 출력한다.

### template

| 필드 | 값 | 설명 |
|---|---|---|
| `file` | 경로 | 템플릿 pptx. 결과물의 슬라이드 크기는 이 파일을 따른다 |
| `mode` | `clone` \| `layout` | `clone`은 템플릿의 예시 슬라이드를 복제한다. `layout`은 레이아웃으로 빈 슬라이드를 만들고 이미지 자리와 상세표를 빌드 시점에 그린다 |
| `source_slide` | 정수 | **`clone` 전용.** 복제할 슬라이드 인덱스(0-based). `null`이면 원인과 대안을 알리며 실패한다 |
| `layout` | 이름 또는 정수 | **`layout` 전용.** 쓸 레이아웃. 이름이면 모든 마스터를 훑어 찾고, 정수면 마스터를 이어붙인 순서의 인덱스다. 없으면 `ValueError`로 곧장 멈춘다 — 있는 레이아웃 이름이 메시지에 나온다 |
| `placeholders` | `{"title": 0, "쪽번호": 12}` | **`layout` 전용.** 채울 placeholder를 **idx로** 지정한다. 이름이 아니라 idx인 이유는 placeholder 이름이 슬라이드를 만들 때마다 `Title 1`·`Content Placeholder 2`처럼 달라지기 때문이다. idx는 레이아웃이 정하므로 고정이다 |
| `content_area` | `[left, top, width, height]` | **`layout` 전용.** 이미지와 상세표를 놓을 본문 영역(EMU). `analyze.py`가 레이아웃 껍데기를 보고 추천값을 계산해 `suggested_template_mapping`에 담는다 — 기본 템플릿이면 `[0, 620688, 9906000, 6095578]`(구분선 아래 ~ 하단바 위)이 나온다. 아예 생략하면 그 대신 실측 기본값 `[-12319, 337940, 9957099, 6331421]`이 쓰인다. 원본 화면설계서에서 잰 값이라 슬라이드 폭을 조금 넘어가는데(의도된 값이다), 두 값 모두 정상 동작한다 |
| `detail_tables` | `{"count": 5, "rows": 4}` | **`layout` 전용.** 만들 상세표 개수와 표당 행 수. 곱이 슬롯 총량이다 |
| `shapes.title` | 도형 이름 | 화면명이 들어갈 자리 |
| `shapes.screen_id` | 도형 이름 | 화면ID가 들어갈 자리 |
| `shapes.image` | 도형 이름 | 스크린샷이 들어갈 자리. 이 도형은 제거되고 그 위치·크기에 이미지가 들어간다 |
| `shapes.detail_tables` | 도형 이름 배열 | **슬롯 순서대로** 나열. `clone`에서는 생략하면 좌→우 자동 정렬 |
| `table_columns` | `{"no": 0, "text": 1}` | 표 안의 번호 열·설명 열 인덱스 |

`shapes`에 `fields`나 `screens.json`의 `meta`와 같은 이름을 넣으면 그 값이 해당 도형에
기록된다. 둘 다 있으면 화면별 `fields`가 문서 전체의 `meta`보다 우선한다.

**두 모드가 `shapes`를 공유하는 이유.** `layout` 모드는 슬라이드를 만든 직후
`placeholders`의 idx로 자리를 찾아 `shapes`의 이름을 붙이고, 새로 그리는 이미지 자리와
상세표에도 `shapes`의 이름을 준다. 그래서 값을 채우는 코드가 `clone`과 완전히 같고,
`verify.py`도 두 모드를 구분하지 않고 `shapes`의 이름으로 결과물을 검증한다. 이름을
안 붙이면 검증이 느슨한 경로로 떨어진다.

**`layout` 모드가 본문 영역을 나누는 방식.** 상세표는 `content_area` 아래쪽에 붙고
폭을 표 개수로 균등 분할한다(정수 나눗셈에서 남는 폭은 마지막 표가 받아 오른쪽 끝을
맞춘다). 행높이는 실제 화면설계서에서 잰 값(`382457, 268746, 496168, 268746` EMU)을
쓰고, 4행을 넘으면 마지막 값을 반복한다. 이미지 자리는 표 위의 나머지를 전부 차지한다.
`rows`가 커서 이미지 자리 높이가 1인치 밑으로 내려가면 `ValueError`로 막는다 —
메시지에 그 `content_area` 높이에서 쓸 수 있는 최대 행 수가 나온다. `content_area`가
슬라이드 위아래를 벗어날 때도 마찬가지다. 이런 오류는 화면별 사고가 아니라 매핑 전체의
설정 오류이므로 화면 루프에 들어가기 전에 한 번에 터진다.

값이 들어가지 않은 placeholder는 빌드 마지막에 지운다. 남겨 두면 PowerPoint가
"제목을 입력하십시오" 안내 문구를 그려 산출물에 빈 자리가 보인다. 쪽번호처럼 자동
필드를 담은 placeholder는 텍스트가 비어 보여도 남긴다.

`layout` 모드 예시:

```json
"template": {
  "file": "work/default-template.pptx",
  "mode": "layout",
  "layout": "화면",
  "placeholders": { "title": 0, "screen_id": 1, "작성일": 10, "문서제목": 11, "쪽번호": 12 },
  "shapes": {
    "title": "제목",
    "screen_id": "화면ID",
    "image": "화면이미지",
    "작성일": "작성일",
    "문서제목": "문서제목",
    "쪽번호": "쪽번호",
    "detail_tables": ["상세표1", "상세표2", "상세표3", "상세표4", "상세표5"]
  },
  "content_area": [0, 620688, 9906000, 6095578],
  "detail_tables": { "count": 5, "rows": 4 },
  "table_columns": { "no": 0, "text": 1 }
}
```

위 `content_area`는 기본 템플릿에 대해 `analyze.py`가 계산해 주는 값 그대로다.
`content_area`를 아예 빼면 대신 실측 기본값 `[-12319, 337940, 9957099, 6331421]`이
쓰인다 — 둘은 다른 값이며, 실제 실행에서 쓰이는 쪽은 `analyze.py`가 넣어 준 값이다.

### 기본 템플릿

사용자가 템플릿을 주지 않으면 `analyze.py`가 `default-template.pptx`를 만든다.
슬라이드 크기는 실측값 9906000 × 6858000 EMU(10.83 × 7.50in)이고, **슬라이드는 한 장도
없다** — 화면 페이지용 레이아웃 `화면` 하나만 들어 있다. 생성 단계가 그 레이아웃으로
슬라이드를 만들기 때문에 복제할 예시 슬라이드가 필요 없다.

레이아웃에는 두 종류가 들어 있다.

- **껍데기 도형 다섯 개** — `상단띠`, `상단띠2`, `구분선`, `화면ID배경`, `하단바`.
  테마 accent1로 칠한 장식이며 값이 들어가지 않는다.
- **placeholder 다섯 개** — idx 0 `제목`, idx 1 `화면ID`, idx 10 `작성일`,
  idx 11 `문서제목`, idx 12 `쪽번호`. 앞의 넷은 빈 텍스트로 시작하고, 쪽번호만 자동
  필드를 살려 둔다. `작성일`·`문서제목`은 표지 메타(`meta`)를 받는 자리이므로
  표지가 없는 Excel이면 그대로 비어 있다 — 그 경우 빈 placeholder로 지워진다.

이미지 자리(`화면이미지`)와 상세표 5개(`상세표1`~`상세표5`, 각 4행 2열 = 20슬롯)는
레이아웃에 없다. `build.py`가 `content_area` 안에 매 슬라이드마다 그린다.

원본 화면설계서의 저작권 문구는 복제하지 않는다. 이 템플릿은 스킬에 코드로 담겨
배포되므로, 넣으면 제3자의 저작권 표기가 모든 사용자 산출물에 박힌다. 그 자리에는
Excel 표지에서 읽은 `문서제목`이 들어간다.

`부제`는 표지에 단독 셀이 두 개 있으면 `meta`로 추출되지만 기본 템플릿에는 대응하는
자리가 없어 쓰이지 않는다 — 사용자 템플릿에 `부제`라는 이름의 도형을 두면 채워진다.

이 경우 `structure-report.json`의 `suggested_template_mapping`을 `template` 섹션에
그대로 복사하면 된다. 도형 이름과 placeholder idx가 고정이라 추측이 필요 없고,
`content_area`도 `analyze.py`가 레이아웃을 보고 계산해 넣어 준다 — 위 `layout` 모드
예시가 바로 그렇게 나오는 값이다.

python-pptx 기본 템플릿이 갖고 있던 나머지 열 개 레이아웃은 파일에 그대로 남는다.
레이아웃을 이름으로 찾으므로 동작에는 영향이 없지만, PowerPoint에서 템플릿을 열면
그 레이아웃들이 보인다.

`build_default_template(path, slide_width_emu=..., slide_height_emu=...)`로 슬라이드
크기를 바꿀 수 있다. 껍데기와 placeholder 좌표는 실측값을 그 비율로 스케일한다.
슬롯 수는 이제 템플릿이 아니라 매핑의 `detail_tables`가 정한다 — 상세가 항상 20건을
넘는 양식이라면 `rows`를 키워 분할을 줄인다. 다만 표 높이가 `rows`에 비례해 커지는
만큼 이미지 자리가 줄어들므로 무한정 키울 수는 없다.

### options

| 필드 | 기본 | 설명 |
|---|---|---|
| `detail_text_source` | `desc` | 상세 표에 넣을 `details` 키 |
| `overflow` | `split` | 슬롯을 넘치면 다음 슬라이드로 분할하고 제목에 `(1/2)` 표시. `build.py`는 이 값을 읽지 않는다 — 분할은 항상 일어난다. 다른 값을 넣어도(예: `none`) 동작은 바뀌지 않는다. 이 필드는 향후 확장을 위해 자리만 있다 |
| `clear_unused_slots` | `true` | 남는 슬롯의 예시 텍스트를 비운다 |

## screens.json

Excel에서 뽑은 중간 산출물이다. 사람이 손으로 고치는 파일이 아니다 — 재추출은 그냥
덮어쓰고, 추출 결과가 어긋나면 이 파일이 아니라 매핑을 고친다. 그래도 파일로 남기는
이유는 셋이다. `build.py`가 Excel을 모르는 채로 있을 수 있고(Excel 픽스처 없이 빌드
로직을 검증한다), 이미지 추출이 느려서 생성 단계만 따로 반복할 수 있으며, 결과가
이상할 때 추출이 틀렸는지 배치가 틀렸는지 갈라 볼 수 있다.

```json
{
  "meta": { "프로젝트명": "이용기관 관리 시스템", "작성일": "2026-08-04",
            "source": "입력.xlsx", "template": "템플릿.pptx" },
  "screens": [
    {
      "id": "B2BISMT1001",
      "name": "이용기관 목록",
      "sheet": "설계_B2BISMT1001",
      "images": ["images/B2BISMT1001.png"],
      "fields": {},
      "details": [
        { "no": "1", "type": "버튼", "element": "[등록] 버튼",
          "desc": "이용기관을 신규로 등록한다", "pos": "상단 우측" }
      ]
    }
  ]
}
```

`details`의 키는 양식마다 다르다. `build.py`는 `options.detail_text_source`가 가리키는
키와 `no`만 사용하므로, 나머지 키는 사람이 참고하도록 그대로 보존된다.

`images`는 작업 디렉토리 기준 상대 경로다.

`meta`는 표지 시트에서 읽은 라벨-값 쌍이 그대로 담긴다(예: `"프로젝트명"`, `"작성일"`,
표지에 단독 셀이 있으면 `"문서제목"`·`"부제"`). `source`(입력 Excel 경로)와
`template`(템플릿 pptx 경로)은 `extract.py`가 채우는 예약 키이므로 표지 값으로
덮이지 않는다. `template.shapes`에 `meta`의 키와 같은 이름이 있으면 `build.py`가
그 값을 해당 도형에 채운다 — 표지가 없어 `meta`가 비었거나 그 키가 없으면
`build.py`는 해당 도형을 아예 건드리지 않는다. 기본 템플릿처럼 그 자리가 원래
빈 텍스트라면 결과물에서도 그대로 비어 있지만, 사용자 템플릿에서 그 도형에
이미 예시 텍스트(예: 날짜 placeholder)가 있었다면 그 텍스트가 결과물에 그대로
남는다 — "빈 채로 남는다"고 단정할 수 없다.
화면별 `fields`에 같은 키가 있으면 `fields`가 `meta`보다 우선한다.

## 경고 코드

| 코드 | 의미 |
|---|---|
| `no-image` | 화면에 연결된 이미지를 찾지 못함 |
| `no-detail` | 상세 표 헤더를 찾지 못함 |
| `text-overflow` | 셀 폭 대비 글자 수가 많아 잘릴 수 있음 |
| `shape-not-found` | 템플릿에서 지정한 도형 이름을 찾지 못함 |
| `slide-split` | 상세가 슬롯을 넘쳐 슬라이드를 나눔 |
| `slot-shortage` | 이 슬라이드에 다 못 담음 |
| `screen-failed` | 해당 화면 생성 실패. 나머지 화면은 계속 생성됨 |
| `image-convert-failed` | EMF/WMF를 PNG로 변환하지 못해 원본을 사용 |
| `orphan-row` | `table` 레이아웃에서 화면ID 없이 시작하는 행 |
