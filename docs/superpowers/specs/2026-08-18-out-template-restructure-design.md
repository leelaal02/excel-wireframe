# 기본 템플릿을 out.pptx 구조로 바꾸고 사진·표 자리를 고정한다

작성 2026-08-18. 상태: 설계 승인됨, 구현 진행.

`2026-08-12-table-position-design.md`(표를 옆으로 옮기는 안)는 이번 범위가 아니다.
표는 계속 아래에 놓는다.

## 문제

사용자가 `out.pptx`를 건넸다. 조직 템플릿(`assets/default-template.pptx`, 레이아웃
23개)에서 화면설계서에 실제로 쓰는 레이아웃 둘만 남긴 정제판이다. 지금의
`default_template.py`가 만드는 기본 템플릿은 이것과 구조가 다르다 — 슬라이드 폭이
다르고, 상단이 단색 막대인데 실물은 메타 정보 표다.

여기에 세 가지가 겹친다.

1. **레이아웃의 표는 슬라이드로 상속되지 않는다.** out.pptx의 `내용설명연결`
   레이아웃은 도형 6개를 갖는데 그 레이아웃으로 슬라이드를 만들면 도형이 0개다.
   PowerPoint는 placeholder만 물려준다. 표가 눈에는 보여도 값을 쓸 대상이 없다.
2. **사진·표 자리가 화면마다 밀린다.** 상세 텍스트가 길면 `_fit_tables`가 표를 위로
   늘리고 그만큼 사진 자리가 줄어, 슬라이드마다 사진 크기가 달라진다.
3. **Excel 원문이 길다.** 실제 샘플(`긴 버전.xlsx`)의 상세 설명은 평균 94자, 최대
   239자다. 화면설계서의 화면설명은 그렇게 쓰지 않는다.

## 설계

### 1. 기본 템플릿 구조

`default_template.py`를 out.pptx 실측으로 다시 만든다. 저작권 문구와 로고 그림은
넣지 않는다 — 스킬은 코드째 배포되므로 제3자 표기가 모든 사용자 산출물에 박힌다
(기존 원칙). 그 자리(하단 좌측)에는 지금처럼 문서제목이 들어간다.

| 항목 | 현행 | 변경 |
|---|---|---|
| 슬라이드 | 9906000 × 6858000 | **9144000 × 6858000** (10 × 7.5in) |
| 레이아웃 이름 | `화면` | **`내용설명연결`** |
| 상단 | accent1 막대 2개 | **메타 표 2개** |
| 본문 | 없음 | **테두리 박스** |

실측값 (EMU, out.pptx `내용설명연결`):

| 도형 | left | top | width | height |
|---|---|---|---|---|
| 메타표1 (18열 1행) | 1 | 0 | 9134931 | 137234 |
| 메타표2 (6열 1행) | 1 | 195617 | 7430165 | 137234 |
| 화면ID 배경 | 7496632 | 188657 | 1635346 | 144000 |
| 본문 박스 | -1 | 404664 | 9131979 | 6264697 |
| 하단바 | 0 | 6716266 | 9144000 | 144000 |
| 쪽번호 | 4370029 | 6716266 | 403943 | 144000 |
| 문서제목 | 0 | 6750725 | 2444995 | 75085 |

표 행 높이는 둘 다 116632, 셀 여백 16616/19087, 글자 6.5pt 굵게. 열 폭:

```
표1  450927 1163077 365539 1163077 299077 1163077 226665 265847 299077
     398769 265877 398769 299077 465284 299077 465231 199407 947077
표2  450927 4254011 398813 930566 398813 997035
```

`화면ID 배경`은 그룹 안에 있어 좌표가 그룹 스케일(x 0.923077)을 거친 값이다. 위 표는
절대 좌표로 환산해 뒀다.

placeholder는 **화면ID(1)·문서제목(11)·쪽번호(12)** 셋만 둔다. 화면명과 작성일은
메타 표가 담당하므로 별도 자리를 만들지 않는다 — out.pptx 구조를 그대로 따르는 것이
이 작업의 목적이다.

`assets/default-template.pptx`를 out.pptx로 교체하고 `user-default.json`을 그 구조에
맞게 갱신한다.

### 2. 메타 표 채우기

레이아웃의 표는 배경으로 비칠 뿐 슬라이드의 도형이 아니라 값을 쓸 수 없다.
처음에는 표를 복제해 같은 좌표에 덮었지만, 그러면 표가 두 겹이 되어 원본을
클릭할 수 없고 테두리가 두 번 그려진다. **원본 표는 그대로 두고 값이 들어갈 칸
좌표에 글자만 올린다**(`add_meta_text_slots`). 도형 이름은 `메타:{라벨}`이다.

값은 라벨 문자열로 셀을 찾아 **바로 오른쪽 칸**에 쓴다. 열 인덱스를 하드코딩하지
않으므로 조직마다 표 구성이 달라도 라벨만 맞으면 동작한다.

글자 서식(크기·굵기·색·글꼴)과 문단 속성(정렬)은 그 칸이 품고 있던 것을 그대로
복사한다. 빈 칸은 그것을 `endParaRPr`에 담고 있다 — PowerPoint가 "다음에 칠 글자의
서식"으로 저장해 두는 자리다. 이걸 안 물려받으면 크기가 상속(기본 18pt)으로 떨어져
0.13인치짜리 메타 표 행이 부풀어 버린다.

`mapping.json` / `user-default.json`의 `template`에 섹션을 더한다.

```json
"meta_table": {
  "tables": ["메타표1", "메타표2"],
  "labels": {
    "프로젝트명": "프로젝트명", "산출물명": "문서제목", "화면명": "title",
    "버전": "버전", "작성자": "작성자", "검토자": "검토자",
    "작성일": "작성일", "수정일": "수정일", "ID": "screen_id",
    "네비게이션": "네비게이션", "화면유형": "화면유형", "알림여부": "알림여부"
  }
}
```

키는 표 안의 라벨, 값은 값을 가져올 이름이다. `title`과 `screen_id`는 화면의
이름·ID를 가리키는 예약어이고, 나머지는 화면별 `fields` → 문서 `meta` 순으로 찾는다.
`meta_table`이 없으면 이 경로 전체를 건너뛴다 — 기존 매핑은 그대로 동작한다.

### 3. 미입력은 빨강 굵게

```python
INPUT_REQUIRED = "입력필요"   # RGB FF0000, bold
```

메타 표 칸과 mapping에 등록된 자리 모두, 값을 찾지 못하면 비우지 않고 이 문자열을
넣는다. 쪽번호처럼 자동 필드(`a:fld`)를 담은 자리만 예외다 — 글자를 쓰면 필드가
사라지므로 값이 없을 때는 그대로 둔다. `drop_empty_placeholders`는 손대지 않는다:
등록된 자리는 입력필요로 채워져 있으므로 지워지지 않고, 등록되지 않은 잉여
placeholder만 지워진다.

`긴 버전.xlsx` 기준으로 12칸 중 버전·작성자·검토자·수정일·네비게이션·화면유형·
알림여부 7칸이 빨강으로 나온다. 사용자는 `meta_overrides`에 한 줄씩 적어 채운다.

서식은 `slide_fill._fill_text_frame`에 `emphasis` 인자를 더해 처리한다. 런을 새로
만들면 셀 서식이 초기화되므로 기존 함수를 확장한다(기존 원칙).

### 4. 사진·표 자리를 비율로 고정

표 높이를 내용에 따라 늘리지 않는다. 본문 영역 높이의 고정 비율로 잡는다.

```python
MEASURED_CONTENT_HEIGHT = DEFAULT_CONTENT_AREA[3]   # 6331421 — ROW_HEIGHTS를 잰 본문
ratio_row_heights(h, rows) = [int(x * h / MEASURED_CONTENT_HEIGHT)
                              for x in measured_row_heights(rows)]
```

- 행 높이 = 실측 행 높이 × (본문 높이 / 기준 본문 높이)
- 표 영역 = 그 합, 하단 정렬, 폭 균등 분할
- 사진 영역 = 그 위 나머지 전부, 안에서 비율 유지 · 위 정렬(가로는 가운데)

기준을 `ROW_HEIGHTS`를 잰 본문 높이로 잡아야 원본 화면설계서와 똑같은 표가 나온다.
out.pptx 본문(6264697)에서는 98.9% 크기가 된다.

**긴 스크린샷의 조각도 같이 맞춰야 한다.** 조각 높이는 여백 띠를 따라가 제각각이라
가로세로 비가 다르고, 그러면 같은 자리에 비율을 지켜 앉힐 때 슬라이드마다 사진
크기가 달라진다. `image_split.slice_image`가 짧은 조각 아래에 흰 여백을 덧대
비를 맞춘다 — 잘라 내지 않으므로 내용은 그대로다.

슬라이드 크기나 레이아웃이 달라져도 같은 비율을 따르므로 모든 화면에서 사진과 표가
같은 자리·같은 크기다.

`_fit_tables`의 역할이 바뀐다. 행 높이는 이제 고정이므로 **글자 크기만** 낮춰
맞춘다(7 → 6.5 → 6pt). 6pt로도 넘치면 지금처럼 `text-overflow` 경고를 남긴다.
`plan_row_heights`로 행을 늘리던 경로는 사라진다.

`row_heights`를 명시로 넘기는 인자는 남긴다 — 기존 테스트와 clone 모드가 쓴다.

### 5. 화면설명 요약

추출과 생성 사이에 단계를 넣는다. Claude가 `screens.json`의 상세를 읽어 화면설계서
어투로 바꿔 `.work/summaries.json`에 쓰고, `build.py`가 있으면 그 값을 셀에 넣는다.

형식은 **요소명 + 개조식 한 줄**, 30~50자를 목표로 한다.

```
원문  화면에 입력/수정한 발행기관 기본정보 전체를 저장한다. 클릭 시 필수항목 및
      유효성 검사를 수행하고, 저장 확인 메시지에 동의하면 저장 후 화면을 재조회한다.
요약  [저장] 기본정보 저장 · 필수·유효성 검사 후 저장, 재조회
```

```json
{ "CPTIPMT1002": { "1": "[저장] 기본정보 저장 · 필수·유효성 검사 후 저장, 재조회" } }
```

화면ID → 상세번호(`no`) → 요약문. 번호는 Excel 값을 그대로 쓰므로(기존 원칙)
재추출해도 키가 유지된다. 파일이 없으면 원문을 그대로 쓴다 — 기존 동작과 호환된다.
사용자가 직접 손볼 수도 있다.

`extract.py`가 `screens.json`을 덮어써도 `summaries.json`은 건드리지 않는다.
