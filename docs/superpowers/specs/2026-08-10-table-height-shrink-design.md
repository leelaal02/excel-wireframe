# 표를 내용에 꼭 맞게 줄인다

## 문제

`2026-08-10-table-height-fit-design.md`는 상세 내용에 맞춰 표를 위로 늘려 슬라이드
넘침을 없앴다. 넘침은 사라졌지만 표가 필요 이상으로 높다.

원인은 그 설계의 4번, **화면 안에서 표 높이를 하나로 통일한다**는 결정이다. 행 높이를
그 화면의 모든 장을 통틀어 최댓값으로 잡으므로, 긴 상세 하나가 모든 장의 표를 밀어
올린다. 실제 샘플에서 긴 버전 1페이지의 첫 행은 4줄이면 되는데 9줄 높이(969645 EMU)로
잡혔다 — 다른 장에 9줄짜리가 하나 있어서다.

| | 표 높이 | 빈 공간 |
|---|---|---|
| 긴 버전 1p | 3.31in | 0.82in (7줄) |
| 긴 버전 2p | 3.31in | 1.05in (9줄) |
| 짧은 버전 | 3.19in | 0 |

표가 먹은 만큼 스크린샷이 줄어든다. 긴 버전 이미지 자리는 6장 모두 3.62in였고, 좌측
메뉴와 상단 탭이 뭉개져 읽히지 않았다. 화면설계서에서 스크린샷은 주인공이다.

## 설계

### 1. 표 높이를 장별로 잡는다

행 높이를 그 장의 상세만 보고 정한다. 표 간(가로로 나란한 5개) 통일은 유지한다 —
행이 어긋나 보이면 안 된다.

장 간 통일을 푸는 것이 안전한 이유는 2패스 구조 때문이다. 배분은 1패스에서 확정되고
2패스는 높이만 구하므로, 장마다 높이가 달라도 **배분을 재계산하지 않아** 순환이
생기지 않는다. 이미지 자리가 장마다 달라지는 것은 `place_image`가 비율을 지켜 축소
배치하므로 이미 잘라둔 조각이 그대로 들어간다.

원래 설계가 통일을 택한 이유 중 순환 회피는 이렇게 해소되고, 남는 것은 "장을 넘길 때
표가 들썩여 보인다"는 심미적 근거뿐이다. 실측한 손실(장당 0.8~1.05in)이 그 값어치보다
크다.

### 2. 줄간격을 0.95배로 좁힌다

계산 계수 `LINE_SPACING`을 1.2에서 1.14(= 1.2 × 0.95)로 낮추고, **동시에** 설명 칸
문단에 줄간격 95%를 실제 서식으로 넣는다.

계수만 낮추면 안 된다. 렌더링 줄높이는 그대로인 채 계산만 작아져 행이 스스로 자라고,
직전 설계가 고친 넘침이 되돌아온다. 계산과 서식은 같은 상수에서 나와야 한다.

### 3. 설명 칸 여백을 9525 → 4762로 줄인다

행당 4763 EMU(4행에 0.02in)로 기여는 작다. 좌우 여백도 함께 줄어 텍스트 폭이
1810506 → 1820032로 넓어지는 부수 효과가 있다.

### 4. 값의 출처를 하나로 모은다

여백 9525가 지금 세 곳에 흩어져 있다.

- `slide_layout.TEXT_CELL_MARGIN` — `detail_text_width`가 쓴다
- `slide_layout.py:353`의 `_format_cell` 호출부 하드코딩 — 셀 서식에 들어간다
- `text_metrics.DEFAULT_MARGIN_TOP` — 행 높이 계산에 들어간다

셋이 어긋나면 계산과 산출물이 달라진다. `text_metrics.CELL_MARGIN` 하나를
`slide_layout`이 가져다 쓰는 형태로 모은다. 줄간격도 `LINE_SPACING_RATIO` 하나에서
계산(`LINE_SPACING`)과 셀 서식이 함께 나온다.

`slide_layout` → `text_metrics` 방향 의존만 생긴다. 직전 설계가 정한 방향 그대로다.

### 5. 문단 속성을 이어붙인 문단에도 물려준다

`slide_fill._fill_text_frame`은 `\n`으로 문단을 나눌 때 런 속성(`rPr`)만 복사하고
문단 속성(`pPr`)은 복사하지 않는다. 줄간격을 넣어도 둘째 문단부터 폰트 기본값으로
돌아가 계산과 어긋난다. `pPr`도 함께 복사한다.

### 6. 폰트 축소는 화면 단위로 유지한다

높이는 장별이지만 글자 크기는 화면 안에서 통일한다. 한 장만 6.5pt면 장을 넘길 때
글자가 커졌다 작아졌다 한다. 어느 한 장이라도 이미지 자리가 `MIN_IMAGE_HEIGHT_EMU`
밑으로 내려가면 그 화면 전체를 한 단계 낮춘다. `_cap_heights`는 장별로 적용한다.

## 검증된 결과

프로토타입을 실제 샘플 두 건에 돌려 얻은 값이다. 예측과 일치했고 넘치는 칸은 0개,
표 하단은 모든 장에서 본문 영역 하단에 오차 0으로 붙었다.

| | 현행 | 이 설계 |
|---|---|---|
| 긴 버전 표 | 3.31 균일 | 2.35 / 2.21 / 1.62 / 2.35 / 2.00 / 2.79 |
| 긴 버전 1p 스크린샷 | 3.62in | 4.58in |
| 짧은 버전 표 | 3.19in | 3.01in |
| 짧은 버전 스크린샷 | 3.73in | 3.91in |

짧은 버전은 1장짜리라 장별 계산의 이득이 없다. 3.01in는 4행에 10줄짜리 설명이 하나
있어서 나오는 값으로, 텍스트 실량이다.

## 변경 지점

| 파일 | 변경 |
|---|---|
| `text_metrics.py` | `BASE_LINE_SPACING`·`LINE_SPACING_RATIO`·`CELL_MARGIN` 신설, `LINE_SPACING`을 곱으로 유도 |
| `slide_layout.py` | `TEXT_CELL_MARGIN`을 `CELL_MARGIN`에서 받고, `_format_cell`에 `line_spacing` 인자 추가, 설명 칸 호출부가 상수를 쓰도록 수정 |
| `slide_fill.py` | `_fill_text_frame`이 `pPr`도 복사 |
| `build.py` | `_fit_tables`가 장별 행 높이 목록을 돌려주고, 호출부가 `page_heights[i]`를 넘긴다 |

`add_detail_table`과 `split_content_area`의 시그니처는 그대로다 — 장별로 다른 값을
넘길 뿐이다.

## 에러 처리

직전 설계와 같다. 화면 단위 예외 격리를 따르고, 가장 작은 글자로도 안 들어가면
`_cap_heights`가 하한을 지키며 비례 축소해 표를 슬라이드 안에 남긴다. 넘친 텍스트는
`text-overflow` 경고가 잡는다. 경고 코드는 아홉 개 그대로다.

## 테스트

**`test_build.py` (수정)**
- "한 화면의 모든 장의 표 높이가 같다"는 **의도적으로 깨진다.** "장별로 자기 내용에
  맞는 높이를 갖는다"로 교체한다
- 장별 높이가 달라도 표 하단은 모든 장에서 본문 영역 하단에 붙는다
- 짧은 상세만 있는 화면은 실측 하한과 같은 높이로 나온다 (회귀 방지)
- 폰트를 낮춰야 하는 화면은 모든 장이 같은 크기를 쓴다

**`test_text_metrics.py` (수정)**
- `LINE_SPACING`이 `BASE_LINE_SPACING × LINE_SPACING_RATIO`와 같다
- 줄간격 계수가 작아지면 같은 줄 수의 행 높이가 낮아진다
- 기존 케이스의 기대값을 새 계수로 다시 잡는다

**`test_slide_layout.py` (추가)**
- 설명 칸 셀에 `line_spacing`이 `LINE_SPACING_RATIO`로 들어간다
- 셀 여백이 `CELL_MARGIN`과 같다 — 계산과 서식이 같은 값을 쓰는지 검사한다

**`test_slide_fill_text.py` (추가)**
- `\n`이 든 텍스트를 채우면 둘째 문단도 첫 문단의 줄간격을 물려받는다

## 하지 않는 것

- 표 간(가로) 행 높이 통일을 풀지 않는다. 행이 어긋나 보이고, 실제로 그렇게 만든
  시안에서 2행 2줄 자리에 6줄짜리가 들어가 넘쳤다
- 상세 번호를 재부여하거나 순서를 바꾸지 않는다. 스크린샷 SoM 뱃지와 대응한다
- `content_area`와 슬라이드 크기는 건드리지 않는다
- 번호 칸 서식(6.5pt, 여백 18000)은 그대로 둔다
- 폰트를 6pt 밑으로 내리지 않는다
