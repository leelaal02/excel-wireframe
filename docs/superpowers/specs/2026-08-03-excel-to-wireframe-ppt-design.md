# Excel 기반 화면설계서 PPT 생성 Skill — 설계

작성일: 2026-08-03
갱신: 2026-08-04 (템플릿 선택 입력화)

## 1. 목표

임의 양식의 화면설계서 Excel을 입력받아 화면설계서 PPT를 자동 생성하는 Claude Skill을 만든다.
PowerPoint 템플릿(.pptx)을 함께 받으면 그 디자인을 유지하고, **템플릿은 선택 입력이다.**
주지 않으면 표준 화면 페이지 구조의 기본 템플릿을 생성해 사용한다.

특정 Excel 양식에 하드코딩하지 않는다. 처음 보는 양식이 들어와도 구조를 분석해
매핑을 도출하고, 사용자 확인을 거쳐 PPT를 생성한다.

## 2. 비목표

- 와이어프레임 이미지를 새로 그리지 않는다. Excel에 삽입된 이미지를 추출해 사용한다.
- PPT 편집 UI를 제공하지 않는다. 생성물은 사용자가 PowerPoint에서 직접 다듬는다.
- 슬라이드 크기 변환(리사이즈)을 하지 않는다. 결과물은 템플릿 파일의 크기를 그대로 따른다.
- 표지·목차 슬라이드를 생성하지 않는다. 화면 페이지만 만든다.

## 3. 핵심 원칙

**`screens.json`이 SSOT(Single Source of Truth)다.**

Excel은 최초 임포트 소스이자 갱신 제안자일 뿐이고, PPT 생성의 진실은 `screens.json`에 있다.
이 원칙에서 다음이 따라온다.

- `build.py`는 Excel을 모른다. openpyxl 의존은 `extract.py`에만 갇힌다.
  `build.py`는 `screens.json`과 `mapping.json`의 `template`·`options` 섹션만 읽고,
  `mapping.excel` 섹션은 보지 않는다.
- Excel 없이 `screens.json`만 직접 작성해도 PPT를 생성할 수 있다.
- 빌드 로직을 Excel 픽스처 없이 단위 테스트할 수 있다.

**충돌 정책: 덮어쓰기 금지 + diff.**

`extract.py`는 `screens.json`이 이미 존재하면 덮어쓰지 않는다. `screens.new.json`에 쓰고
차이를 보고한 뒤, 반영 여부는 사용자가 결정한다. 사람이 손본 내용이 Excel 재추출로
소실되지 않는다.

## 4. 아키텍처

```
excel-to-wireframe-ppt/
├── SKILL.md                    # Claude가 읽는 절차서
├── scripts/
│   ├── default_template.py     # 템플릿 미제공 시 쓸 기본 템플릿 생성
│   ├── analyze.py              # Excel + 템플릿 구조 스캔 → structure-report.json
│   ├── extract.py              # mapping.json 기반 추출 → screens.json + images/
│   └── build.py                # screens.json + 템플릿 → 결과.pptx
└── references/
    └── mapping-schema.md       # mapping.json / screens.json 필드 설명
```

작업 산출물은 입력 Excel 옆의 작업 디렉토리에 모인다.

```
<작업폴더>/
├── structure-report.json       # analyze 산출물 (Claude가 읽는 중간물)
├── mapping.json                # 양식 해석 결과. 재사용됨
├── screens.json                # SSOT
├── images/                     # 추출된 와이어프레임 이미지
└── output/화면설계서.pptx       # 최종 산출물
```

### 판단과 실행의 분리

Claude가 판단하는 지점은 세 곳뿐이고, 파일 조작은 전부 결정론적 스크립트가 맡는다.

1. `analyze.py` 실행 → 구조 리포트 생성
2. **[판단①]** Claude가 리포트를 읽고 `mapping.json` 작성 → 표로 사용자에게 제시하고 확인
3. `extract.py` 실행 → `screens.json` + `images/`
4. **[판단②]** Claude가 추출 결과 요약(화면 N개, 이미지 M개, 누락 K건) 보고
5. `build.py` 실행 → `output/화면설계서.pptx`
6. **[판단③]** 생성물을 재파싱해 슬라이드 수·텍스트·이미지를 검증하고 리포트

`mapping.json`이 이미 있으면 1~2단계를 건너뛴다.

### 의존성

Python 3.13 기준. 스킬 시작 시 확인하고 없으면 설치한다.

```
python-pptx, openpyxl, Pillow
```

## 5. 데이터 모델

### mapping.json

양식 해석 결과. 같은 양식을 재사용할 때 분석 단계를 건너뛰게 해준다.
아래는 샘플(`짧은 버전.xlsx` + 원본 PPT)에 대해 실제로 생성될 값이다.

```json
{
  "version": 1,
  "excel": {
    "layout": "sheet-per-screen",
    "sheet_include": "^설계_",
    "screen_meta": {
      "cell": "A1",
      "pattern": "화면설계서\\s*-\\s*(?P<id>\\S+)\\s*\\((?P<name>.+)\\)"
    },
    "detail": {
      "header_scan_column": "A",
      "header_marker": "No.",
      "columns": { "no": "A", "type": "B", "element": "C", "desc": "D", "pos": "E" }
    }
  },
  "template": {
    "file": "화면설계서_저작권_발행기관.정산처_발행기관관리_v1.0_20260427.pptx",
    "mode": "clone",
    "source_slide": 1,
    "shapes": {
      "title": "제목 13",
      "screen_id": "텍스트 개체 틀 14",
      "image": "그림 18",
      "detail_tables": ["표 7", "표 10", "표 11", "표 12", "표 15"]
    },
    "table_columns": { "no": 0, "text": 1 }
  },
  "options": {
    "detail_text_source": "desc",
    "overflow": "split",
    "clear_unused_slots": true
  }
}
```

- `excel.layout`: `table` | `sheet-per-screen`
- `template.mode`: `clone`(예시 슬라이드 복제) | `layout`(빈 레이아웃 + 플레이스홀더)
- `template.file`: 복제 소스가 될 pptx. 생성물의 슬라이드 크기는 이 파일을 따른다.
- `template.shapes.detail_tables`: **표가 여러 개인 경우 슬롯 순서대로 나열**한다.

### screens.json (SSOT)

```json
{
  "meta": {
    "title": "화면설계서",
    "source": "짧은 버전.xlsx",
    "template": "화면설계서_저작권_...pptx"
  },
  "screens": [
    {
      "id": "B2BISMT1001",
      "name": "이용기관 목록",
      "images": ["images/B2BISMT1001.png"],
      "fields": {},
      "details": [
        { "no": "1", "type": "버튼", "element": "[등록] 버튼",
          "desc": "이용기관을 신규로 등록하는 버튼. …", "pos": "버튼영역 (상단 우측)" }
      ]
    }
  ]
}
```

`details`의 키는 양식마다 다를 수 있다. 스키마는 이 가변성을 허용하고,
`build.py`는 `options.detail_text_source`가 지정한 키를 표에 넣는다.

`fields`는 화면 단위의 부가 값(설명·비고 등)을 담는 자유 키 사전이다. 샘플처럼
상세 표만 있는 양식에서는 비어 있고, `table` 양식에서 화면별 설명 컬럼이 있을 때 채워진다.
`mapping.template.shapes`에 같은 이름의 자리가 있으면 그 도형에 기록된다.

## 6. Excel 양식 대응

실무 화면설계서 Excel은 두 형태다. `mapping.excel.layout` 한 필드로 구분한다.

**`table`** — 1행 = 1화면. 컬럼이 화면ID·화면명·설명·비고.
헤더 행 위치와 컬럼 인덱스를 매핑에 기록한다.

**`sheet-per-screen`** — 1시트 = 1화면. 샘플이 이 형태이며, 다음 세 가지 처리가 필요하다.

1. **시트 필터** — 워크북에는 화면이 아닌 시트가 섞여 있다(`표지`, `테스트_*`, `비교결과요약`).
   `sheet_include` 정규식에 맞는 시트만 화면으로 취급한다.
2. **결합 셀 파싱** — 화면ID와 화면명이 한 셀에 들어 있다
   (`화면설계서 - B2BISMT1001 (이용기관 목록)`). `screen_meta.pattern`의 명명 그룹
   `id`/`name`으로 분리한다. 패턴이 안 맞으면 셀 전체를 `name`으로 두고 `id`는 시트명에서 딴다.
3. **상세 표 헤더 탐색** — 상세 표의 시작 행은 위쪽 이미지 크기에 따라 달라지므로 고정할 수 없다.
   `header_scan_column`을 위에서부터 훑어 `header_marker`(`"No."`)와 일치하는 행을 헤더로 잡고,
   그 다음 행부터 빈 행이 나올 때까지를 상세로 읽는다.

`table` 레이아웃에서 한 화면의 상세가 여러 행에 걸친 경우는 `detail.mode`로 잡는다.

- `grouped-rows`: 화면ID가 비어 있는 후속 행은 직전 화면의 상세 행으로 귀속
- `merged-cells`: 병합 셀 범위로 화면 경계를 판정
- `none`: 상세 표 없음

## 7. Excel 삽입 이미지 추출

가장 깨지기 쉬운 부분이라 2단 방어로 간다.

**1차** — `openpyxl`의 `ws._images`로 이미지와 앵커 셀(`from.row`/`from.col`)을 읽는다.
`sheet-per-screen`이면 시트명으로, `table`이면 앵커 행이 속한 화면 행 범위로 귀속시킨다.

**2차 폴백** — `.xlsx`를 zip으로 직접 열어 `xl/media/`의 바이너리와
`xl/drawings/drawing*.xml`의 앵커를 파싱한다. openpyxl이 놓치는 형식(EMF/WMF, 그룹 도형)이
있으므로, 1차에서 잡힌 이미지 수보다 `xl/media/`의 파일이 많으면 자동으로 폴백한다.

저장 규칙은 `images/<화면ID>.png`. 한 화면에 여러 장이면 `-1`, `-2` 접미사를 붙이고
슬라이드에 순서대로 배치한다.

EMF/WMF는 일부 환경에서 PPT에 표시되지 않으므로 Pillow로 PNG 변환을 시도하고,
실패하면 원본을 넣고 경고에 남긴다.

## 8. 템플릿 대응

**템플릿 미제공 시** — `analyze.py`가 기본 템플릿을 생성해 그것을 쓴다.
16:9(13.33 × 7.50 in) 슬라이드에 상단 제목 바(`제목`, `화면ID`), 가운데 이미지 자리
(`화면이미지`), 하단에 상세 표 5개(`상세표1`~`상세표5`, 각 4행 = 20슬롯)를 배치한다.
저작권 있는 실제 템플릿을 스킬에 번들할 수 없으므로 코드로 생성한다. 도형 이름이 고정이라
매핑을 자동으로 채울 수 있고, 테스트 픽스처도 같은 생성기를 재사용한다.

사용자에게 템플릿을 먼저 요구하지 않는다. 기본 템플릿으로 결과를 만들어 보여준 뒤,
원하는 양식이 있으면 받아 다시 생성한다. 빈손으로 되묻는 것보다 결과물을 놓고
판단하는 편이 빠르다.

**템플릿 제공 시** — `analyze.py`가 템플릿을 열어 예시 슬라이드 존재 여부를 판정한다.
도형에 실제 텍스트가 채워진 슬라이드가 있으면 `clone`, 빈 레이아웃뿐이면 `layout`이다.
샘플은 `clone` 모드이며 소스는 원본 PPT의 slide[1]이다.

**clone 모드** — python-pptx에 슬라이드 복제 API가 없으므로, 슬라이드 XML을 `deepcopy`하고
이미지·차트 등 관계(rels)를 새 슬라이드에 재등록하는 헬퍼를 직접 구현한다.
템플릿의 서식·색·로고가 그대로 유지되는 것이 이 방식의 이점이다.

소스 슬라이드가 여러 장인 pptx(샘플의 39장)에서는 `source_slide` 인덱스로 한 장만 지목하고
나머지는 무시한다. 결과물은 소스 pptx의 슬라이드 크기를 그대로 승계하므로 리사이즈가 없다.

**layout 모드** — `add_slide(layout)` 후 플레이스홀더를 채운다.

**자리 식별** — 템플릿 도형의 이름, 또는 도형 안의 텍스트(`{{화면명}}`, `화면명`, `[화면 이미지]`)로
매칭한다. 매칭 실패 시 위치·크기 휴리스틱으로 후보를 뽑는다(가장 큰 그림/빈 사각형 = 이미지 자리,
상단의 넓고 낮은 텍스트박스 = 제목). 휴리스틱 결과는 반드시 매핑 확인 단계에서 사용자에게 보여준다.

**이미지 배치** — 이미지 자리 도형의 위치·크기를 읽어 종횡비를 유지한 채 맞춰 넣고,
남는 공간은 가운데 정렬한다. 원본 도형은 삭제한다.

### 다중 표 슬롯 채우기

샘플 템플릿은 상세 표가 하나가 아니라 **4행 2열 표 5개가 하단에 가로로 나란히** 놓여
총 20슬롯을 이룬다. 상세 항목은 이 슬롯들에 순서대로 흘려 넣는다.

1. `shapes.detail_tables`에 나열된 표를 순서대로 잡는다. 이름이 없으면 좌→우
   (`left` 오름차순, 같으면 `top` 오름차순)로 정렬해 순서를 정한다.
2. 각 표의 행 수를 세어 슬롯 총량을 구한다(샘플: 5 × 4 = 20).
3. 상세 항목을 표1의 r0…r3 → 표2의 r0…r3 → … 순으로 채운다.
   번호 칸에는 Excel의 `No.` 값을 그대로 넣는다. 이 번호가 스크린샷의 SoM 뱃지와 대응하므로
   재부여하지 않는다.
4. 남는 슬롯은 `clear_unused_slots`가 참이면 번호·설명을 모두 비운다(행은 삭제하지 않는다).
5. 셀에 값을 쓸 때 기존 런의 서식(폰트·크기·색)을 보존한다. 첫 런의 텍스트만 교체하고
   나머지 런은 제거하는 방식으로 처리한다.

## 9. 넘침 처리

슬롯 총량을 넘는 상세 항목은 다음 슬라이드로 넘긴다. 소스 슬라이드를 한 번 더 복제해
이어지는 항목을 채우고, 제목에 `(1/2)`, `(2/2)`를 붙인다. 이미지는 각 장에 동일하게 넣는다.

셀 안에서 텍스트가 길어 잘리는 경우는 자동 축소하지 않는다. 대신 잘릴 가능성이 있는 셀을
글자 수 기준으로 추정해 경고 목록에 올린다. 서식 붕괴보다 사람이 확인하는 편이 낫다.

분할이 발생한 화면은 최종 리포트에 기록한다.

## 10. 에러 처리

원칙은 **부분 산출물 + 경고 목록**이다. 화면 40개 중 3개가 실패했다고 전체가 실패하면 안 된다.

- 화면 단위로 예외를 격리한다. 실패한 화면은 "생성 실패" 표시 슬라이드로 채우고 나머지를 완성한다.
- 최종 리포트에 다음을 화면ID와 함께 나열한다: `이미지 없음`, `텍스트 잘림 가능`,
  `템플릿 자리 못 찾음`, `슬라이드 분할됨`, `슬롯 부족`, `생성 실패`.
- Excel 열기 실패, 템플릿 손상 같은 전체 중단 오류는 원인과 조치 방법을 함께 출력한다.
- 콘솔 출력은 UTF-8로 강제한다. Windows 기본 코드페이지(cp949)에서 한글이 깨지는 것을
  샘플 분석 중 확인했다.

## 11. 테스트

픽스처 생성 스크립트로 샘플을 만들어 E2E로 돌린다.

- Excel 2종: `table` 형, `sheet-per-screen` 형 (각각 삽입 이미지 포함)
- 템플릿 3종: 예시 슬라이드형(표 여러 개), 빈 레이아웃형, 기본 생성 템플릿
- Excel 2종 × 템플릿 2종(예시형·기본 생성) 조합 전부 실행. 빈 레이아웃형은 판정만 확인한다
- 실제 샘플(`짧은 버전.xlsx` + 원본 PPT)로 회귀 테스트

검증은 생성된 `.pptx`를 다시 파싱해 대조한다.

- 슬라이드 수가 화면 수(+ 분할분)와 일치하는가
- 각 슬라이드 제목에 화면명이 들어갔는가
- 상세 항목 수와 표에 채워진 슬롯 수가 일치하는가
- 이미지가 있는 화면의 슬라이드에 그림 도형이 존재하는가
- 슬라이드 크기가 소스 pptx와 같은가

`build.py`는 `screens.json` 픽스처만으로 단위 테스트한다. Excel 없이 검증 가능한 것이
SSOT 구조의 이점이다.

## 12. 샘플 분석 결과 (2026-08-03)

### 입력 파일

| 파일 | 내용 |
|---|---|
| `짧은 버전.xlsx` | 시트 4개. 화면 1개(`설계_B2BISMT1001`), 상세 16건, 스크린샷 1장 |
| `화면설계서_저작권_...20260427.pptx` | 39장. 10.83 × 7.50 in. slide[1]이 표준 화면 페이지 |
| `화면설계서_페이지2.pptx` | 1장. 13.33 × 7.50 in. 위 파일 slide[1]을 뽑아낸 것 |

### 확정 사항

- 상세 표에는 Excel의 **`상세 설명`(D열)만** 넣는다. 원본 PPT와 동일한 형태다.
- 슬라이드 크기는 **10.83 in**. 따라서 복제 소스로 **원본 PPT의 slide[1]**을 쓴다.
  `화면설계서_페이지2.pptx`는 16:9로 리사이즈되며 도형이 우측으로 밀려 있어
  (표7이 `x=-0.01` → `x=1.24`) 소스로 쓰지 않는다.
- 생성 범위는 **화면 페이지만**. 표지·목차는 만들지 않는다.
- `테스트_*` 시트(단위테스트 케이스 17건)와 `비교결과요약` 시트는 **무시**한다.

### 표준 화면 페이지 구조 (원본 slide[1])

| 도형 | 역할 | 위치·크기(in) |
|---|---|---|
| `제목 13` (TITLE) | 화면명 | (4.07, 0.00) 1.38 × 0.16 |
| `텍스트 개체 틀 14` (BODY) | 화면ID | (8.88, 0.21) 1.93 × 0.15 |
| `그림 18` (PICTURE) | 스크린샷 | (-0.01, 0.37) 10.89 × 5.11 |
| `표 7` / `표 10` / `표 11` / `표 12` / `표 15` | 상세 슬롯 4개씩 | y=5.75, x=-0.01 / 2.16 / 4.33 / 6.49 / 8.66, 각 2.16 폭 |

상세 슬롯은 총 20개다. 샘플 화면의 상세는 16건이므로 4슬롯이 빈다.

## 13. 열린 항목

- 화면이 2개 이상인 Excel 샘플은 아직 확인하지 못했다. 시트 필터와 화면 순서 정렬
  (시트 순서를 따를지, 화면ID 정렬을 따를지)은 구현 시 시트 순서를 기본으로 하고,
  다중 화면 샘플을 받으면 재검토한다.
- 상세가 20건을 초과하는 화면이 아직 없어 분할 동작은 픽스처로만 검증한다.
