# 상세표가 슬라이드를 넘지 않게 한다

## 문제

PowerPoint 표의 행 높이는 **하한**이다. `ROW_HEIGHTS`로 지정한 값보다 셀 텍스트가
길면 렌더링 시 행이 스스로 자라고, 표 전체가 본문 영역 아래로 밀려 슬라이드 밖으로
나간다. `split_content_area`가 계산한 표 높이는 그 순간 무의미해진다.

현재는 `slide_fill.estimate_overflow`가 글자 수로 넘침을 추정해 `text-overflow`
경고만 남긴다. 배치는 손대지 않는다.

## 실측

기본 서식(설명 칸 5.03cm, 7pt, `count=5`, `rows=4`) 기준으로 샘플 두 개를 쟀다.

| | 상세 건수 | 최장 | 7pt 초과 | 6.5pt | 6pt |
|---|---|---|---|---|---|
| 짧은 버전 | 16건 | 241자 | 9건 (56%) | 8건 | 7건 |
| 긴 버전 | 93건 | 191자 | 34건 (37%) | 29건 | 17건 |

7pt에서 행별 허용 줄 수는 `[3, 2, 4, 2]`, 6pt에서 `[4, 2, 5, 2]`다. 폰트를 6pt까지
낮춰도 절반 남짓만 잡힌다 — 241자는 6pt에서도 11줄쯤 필요하다. **폰트 축소는 해법이
아니다.**

반면 20슬롯을 꽉 채운 최악 케이스의 필요 표 높이는

| 폰트 | 필요 표 높이 | 남는 이미지 자리 |
|---|---|---|
| 7pt | 5.74cm | 11.85cm |
| 6pt | 4.17cm | 13.42cm |

가용 15.05cm(본문 17.59 − 이미지 최소 2.54) 안에 여유롭게 들어간다. **표를 위로
늘리면 폰트를 건드리지 않고도 담긴다.**

## 설계

### 1. 표 높이를 내용 기반으로 계산한다

`ROW_HEIGHTS`의 실측값을 하한으로 두고, 슬롯에 들어갈 텍스트가 몇 줄인지 계산해
필요한 행 높이를 잡는다. 표의 아래 끝은 본문 영역 하단에 고정하고 **상단을 위로**
올린다. 이미지 자리는 남은 위쪽 전부다.

줄 수는 `unicodedata.east_asian_width`로 전각/반각을 나눠 폭을 누적해 추정한다.
폰트 메트릭 없이도 현재의 "글자 수 × 인치" 근사보다 정확하다.

### 2. 폰트 축소는 2차 방어다

표가 커져 이미지 자리가 `MIN_IMAGE_HEIGHT_EMU`(2.54cm) 밑으로 내려갈 때만
설명 칸을 7 → 6.5 → 6pt로 낮춘다. 번호 칸 6.5pt는 건드리지 않는다 — 번호는
한두 글자라 넘칠 일이 없다. 평상시에는 원본 실측 서식 7pt가 그대로 유지된다.

### 3. 6pt로도 안 들어가면 경고만 남긴다

지금과 같다. 넘치는 채로 내보내고 `text-overflow` 경고를 남겨 사람이 문장을
고치도록 한다. **경고 코드는 아홉 개를 유지한다** — 폰트 축소는 정상 동작이므로
경고 대상이 아니다.

### 4. 화면 안에서는 표 높이를 하나로 통일한다

한 화면이 여러 장으로 나뉘면 장마다 상세가 달라 표 높이도 달라진다. 그러면 이미지
자리가 장마다 달라지고, `plan_cuts`의 `target_h`가 이미지 자리에 의존하므로
**표 높이 → 이미지 자리 → 분할 → 상세 배분 → 표 높이**라는 순환이 생긴다.

그 화면의 모든 페이지 중 가장 높은 표에 맞춰 전 페이지를 통일해 순환을 끊는다.
장을 넘겨도 표 위치가 흔들리지 않아 보기에도 낫다.

순환을 끊는 방법은 **2패스**다. 반복해 수렴시키지 않는다.

1. **1패스 — 배분을 확정한다.** 현행 고정 표 높이(`ROW_HEIGHTS`)로 이미지 자리를
   잡고, 지금과 똑같이 `plan_pages`를 돌려 조각과 상세 배분을 얻는다.
2. **2패스 — 높이를 확정한다.** 1패스에서 나온 페이지별 실제 상세로 표 높이를
   계산하고, 그 화면의 최댓값을 취해 전 페이지에 적용한다.
3. **배분은 재계산하지 않는다.** 표가 커지면 이미지 자리가 줄지만, `place_image`가
   비율을 유지해 축소 배치하므로 이미 잘라둔 조각이 그대로 들어간다. 넘치지 않는다.

배분을 다시 돌리지 않는 것이 핵심이다. 다시 돌리면 이미지 자리가 바뀌어 조각 수가
바뀌고, 조각 수가 바뀌면 배분이 바뀌어 표 높이가 또 바뀐다. 2패스로 끊으면 결과가
결정적이고, 대가는 이미지가 조금 작아지는 것뿐이다.

이미지가 지나치게 작아지는 경우는 폰트 축소(2번)가 받는다 — 이미지 자리가 최소
높이 밑으로 내려갈 때 표를 낮춰 자리를 되찾는다.

## 모듈 경계

**신규 `text_metrics.py`** — 순수 함수만 둔다. 슬라이드도 openpyxl도 모른다.

- `text_lines(text, width_emu, size_pt) -> int` — 폭 안에서 몇 줄인지
- `row_height(lines, size_pt, margin_top, margin_bottom) -> int` — 줄 수 → EMU
- `plan_row_heights(texts, width_emu, size_pt, floors) -> list[int]` — 슬롯별 높이,
  `floors`(=`ROW_HEIGHTS`)를 하한으로

`slide_layout`과 `slide_fill`이 이것을 쓴다. 반대 방향 의존은 없다.

## 변경 지점

| 파일 | 변경 |
|---|---|
| `text_metrics.py` (신규) | 위 세 함수 |
| `slide_layout.py` | `split_content_area(..., row_heights=None)`, `add_detail_table(..., row_heights=None, size_pt=7.0)` — 인자 추가. 안 넘기면 현행과 동일 |
| `build.py` | 화면 단위 표 높이 산출을 `plan_pages` 앞에 배치. 산출값을 이미지 분할과 슬라이드 생성에 함께 넘긴다 |
| `slide_fill.py` | `estimate_overflow`를 `text_metrics` 기반으로 교체 |

기본값을 두므로 기존 호출은 전부 그대로 동작한다.

## 에러 처리

- 화면 단위로 예외를 격리하는 기존 원칙을 그대로 따른다. 높이 계산이 실패하면 그
  화면만 현행 고정 높이로 떨어지고 나머지는 새 경로로 간다.
- `split_content_area`의 기존 `ValueError`(rows가 과해 이미지 자리가 1인치 미만)는
  유지한다. 새 경로에서는 폰트 축소를 거친 뒤에도 미달일 때만 던진다.

## 하지 않는 것

- 텍스트를 말줄임표로 자르지 않는다. 설계서는 내용이 자산이다.
- 넘치는 항목을 다음 슬라이드로 밀지 않는다. 상세와 이미지 조각의 대응이 깨진다.
- 슬라이드 크기와 `content_area`는 건드리지 않는다.
- 번호 칸 폰트와 열 폭 비율(`COL_WIDTH_RATIO`)은 그대로 둔다.
