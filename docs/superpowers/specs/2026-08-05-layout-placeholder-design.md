# 레이아웃 선택 + placeholder 채우기 방식 설계

**작성일:** 2026-08-05

## 목표

슬라이드를 만드는 방식을 바꾼다. 지금은 템플릿의 예시 슬라이드를 통째로 복제해
그 도형에 값을 채운다. 앞으로는 **레이아웃을 골라 새 슬라이드를 추가하고, 그 레이아웃이
물려주는 placeholder에 값을 채운다.** 디자인은 레이아웃이 담당하고, 스킬은 레이아웃 선택과
데이터 채우기만 한다.

함께 `screens.json`을 SSOT에서 중간 산출물로 강등한다.

## 왜 하는가

기본 템플릿이 상단 띠·하단 바·쪽번호 같은 껍데기를 슬라이드 도형으로 다시 그리고 있다.
그 껍데기는 레이아웃이 이미 제공하는 것이라 중복이다. 레이아웃을 쓰면 껍데기를 한 곳에서
관리하고, PowerPoint에서 레이아웃만 고쳐도 전 슬라이드에 반영된다.

`screens.json`의 덮어쓰기 보호는 사람이 그 파일을 손볼 것을 전제한 장치인데, 실제 사용
방식은 Excel → PPT 자동 생성이다. 사람이 손보지 않는 파일을 보호하느라 재추출마다
diff 확인 단계가 끼어든다.

## 조사로 확인한 사실

실제 샘플(`화면설계서_저작권_발행기관.정산처_발행기관관리_v1.0_20260427.pptx`,
마스터 2개 · 레이아웃 23개)과 python-pptx 1.0.2로 확인했다.

### 1. 레이아웃의 placeholder는 세 종류뿐이다

화면 페이지가 쓰는 `내용설명연결` 레이아웃 기준:

| placeholder | idx | left | top | width | height | 원본에서의 정체 |
|---|---|---|---|---|---|---|
| TITLE | 0 | 3722514 | 0 | 1260000 | 144000 | `제목` |
| BODY | 2 | 8121353 | 188640 | 1766860 | 138032 | `화면ID` |
| DATE | 10 | 8146752 | 0 | 504000 | 144000 | `작성일` |

**BODY는 본문 영역이 아니다.** 1.93 × 0.15 in짜리 우측 상단 칸이고, 화면ID가 들어가던
자리다. 따라서 BODY를 기준으로 이미지·표를 배치할 수 없다.

이미지 자리와 상세표 5개에 해당하는 placeholder는 **어느 레이아웃에도 없다.** 원본에서도
그 둘은 슬라이드에 직접 그린 일반 도형이었다.

### 2. 껍데기는 지금도 레이아웃이 담당하고 있다

`clone_slide`는 원본 슬라이드의 도형만 복사하고 레이아웃 참조는 그대로 물려준다.
상단띠·하단바·로고·쪽번호는 이미 레이아웃에서 렌더링된다. 방식을 바꿔도 이 부분은
달라지지 않는다.

### 3. `add_slide(layout)`은 TITLE과 BODY만 상속한다

python-pptx는 date/footer/slidenumber 계열 placeholder를 복제하지 않는다. 실제로
`내용설명연결`로 슬라이드를 만들면 idx 0과 2만 생기고 DATE(idx 10)는 빠진다.
**레이아웃의 placeholder XML을 `copy.deepcopy` 해서 슬라이드 `spTree`에 넣으면**
`slide.placeholders[10]`으로 잡히고 값도 써진다 — 검증 완료.

### 4. 레이아웃 편집은 우회로가 필요하지만 된다

`layout.shapes`(`LayoutShapes`)에는 `add_shape`·`add_textbox`가 없다. 임시 슬라이드에
도형을 그린 뒤 그 XML을 레이아웃 `spTree`에 append하면 저장·재로드 후에도 유지된다.

레이아웃 placeholder의 좌표 변경은 그냥 된다. 변경한 좌표를 새 슬라이드가 그대로 상속한다.

### 5. 슬라이드 0장 pptx도 정상이다

저장·재로드 모두 문제없다. 기본 템플릿에 예시 슬라이드를 둘 필요가 없다.

## 설계

### 두 모드 병존

| mode | 언제 | 슬라이드를 만드는 법 |
|---|---|---|
| `clone` | 템플릿에 예시 슬라이드가 있을 때 | 기존 그대로 — 예시 슬라이드를 복제 |
| `layout` | 예시 슬라이드가 없을 때, 기본 템플릿을 쓸 때 | 레이아웃을 골라 `add_slide` |

`analyze.py`의 `suggest_mode`가 이미 이 판정을 한다. 지금은 `layout`으로 판정되면
`build.py`가 `ValueError`로 멈추는데, 그 구멍을 메우는 것이 이 작업이다.

`clone`을 남기는 이유는 **상세표의 서식** 때문이다. 예시 슬라이드를 복제하면 표의 테두리·
음영·폰트·여백이 원본 그대로 따라온다. `layout` 모드는 표를 코드가 새로 만들므로 그
서식을 코드가 정해야 하고, 사용자 템플릿의 표 디자인과 달라질 수 있다. 사용자 템플릿의
디자인을 정확히 따르는 일은 `clone`이 이미 잘한다.

`layout` 모드의 표 서식은 **코드 상수**로 둔다(현재 `default_template.py`가 쓰는 실측값).
PPT 표 스타일 ID 지정이나 레이아웃에 표 견본을 심는 방식은 채택하지 않는다 — 설정이
늘어나는 만큼의 이득이 없다.

### build.py의 layout 모드 흐름

화면(페이지) 하나마다:

1. `slide = prs.slides.add_slide(layout)` — 레이아웃이 껍데기·디자인을 제공한다
2. **placeholder 보충 상속** — 레이아웃에 있으나 python-pptx가 복제하지 않은
   placeholder(date/footer/slidenumber)의 XML을 슬라이드로 복제한다
3. **placeholder 값 채우기** — 제목, 화면ID, 그리고 `meta`/`fields`에서 온 값
4. **이미지 배치** — `content_area` 상단에 종횡비를 유지해 넣는다 (`place_image` 재사용)
5. **표 생성** — `content_area` 하단에 표 N개를 만든다
6. **슬롯 채우기** — `fill_slots`를 그대로 재사용한다
7. **빈 placeholder 제거** — 값이 들어가지 않은 placeholder는 지운다. 남기면
   PowerPoint에서 "제목을 입력하십시오" 프롬프트로 보인다

`slide_clone.py`는 `clone` 모드 전용으로 그대로 남는다.

### 채운 placeholder에 이름을 붙인다

③에서 값을 채운 뒤 **도형 이름을 mapping의 `shapes`가 정한 이름으로 바꾼다.**

`verify.py`는 `template.shapes.title` 이름으로 제목 도형을 찾아 화면명 반영과 상세 항목
수를 검사한다(`_title_texts`). 이름을 안 붙이면 `title_name`이 `None`이 되어 슬라이드의
모든 텍스트를 제목 후보로 보는 느슨한 경로로 떨어지고, 상세 항목 수 검사가 오탐을 낸다.

placeholder 이름은 `add_slide`가 `Title 1`, `Content Placeholder 2`처럼 그때그때
정하므로 그대로 두면 검증에 쓸 수 없다. 값을 채운 뒤 `제목`·`화면ID`로 이름을 바꾸면
`verify.py`를 고치지 않아도 되고, 사용자가 PowerPoint에서 열었을 때 선택 창의 이름도
읽을 만해진다. 표도 마찬가지로 `상세표1`…`상세표N`으로 이름을 붙이고, 그 목록을
`shapes.detail_tables`에 담아 검증이 표를 찾을 수 있게 한다.

즉 layout 모드의 mapping은 **`placeholders`(어느 idx에서 찾을지)와 `shapes`(어떤 이름으로
남길지)를 함께 쓴다.** 중복이 아니라 역할이 다르다.

### mapping.json의 template 섹션

```json
{
  "file": "work/default-template.pptx",
  "mode": "layout",
  "layout": "내용설명연결",
  "placeholders": { "title": 0, "screen_id": 2, "작성일": 10 },
  "shapes": { "문서제목": "문서제목" },
  "content_area": [0, 620688, 9906000, 6050000],
  "detail_tables": { "count": 5, "rows": 4 },
  "table_columns": { "no": 0, "text": 1 }
}
```

| 필드 | 의미 |
|---|---|
| `layout` | 레이아웃 이름 또는 인덱스. 마스터가 여러 개면 전체를 훑는다. 이름이 중복이면 첫 번째를 쓰고 경고한다. 못 찾으면 `ValueError` |
| `placeholders` | **이름이 아니라 idx로 지정한다.** 이름은 슬라이드마다 `Title 2`, `제목 13`처럼 달라지지만 idx는 레이아웃이 고정한다. 키는 `title`·`screen_id`와 자유 키(`meta`/`fields`에서 값을 찾는다) |
| `shapes` | clone 모드와 같은 이름 기반 경로. layout 모드에서도 레이아웃이 물려준 일반 도형을 이름으로 찾을 때 쓴다 |
| `content_area` | `[left, top, width, height]` EMU. 이미지와 표가 들어갈 영역 |
| `detail_tables` | 표 개수와 표당 행 수. clone 모드의 `shapes.detail_tables`(표 이름 배열)와는 다른 필드다 — clone은 이미 있는 표를 이름으로 찾고, layout은 없는 표를 만들기 때문에 필요한 정보가 다르다 |

`content_area`는 `analyze.py`가 레이아웃을 스캔해 추천값을 계산하고
`suggested_template_mapping`에 담는다. placeholder와 껍데기 도형이 차지하지 않은 가장 큰
사각을 찾는 방식이다. 추정이 빗나가면 사람이 mapping.json에서 고친다.

### content_area 분할

```
content_area
├── 이미지 영역 : 위쪽 나머지 전부
└── 표 영역     : 아래쪽, 높이 = 행높이 실측값 × rows
```

표는 `content_area` 폭을 `count`개로 균등 분할해 좌→우로 놓는다. 열 폭은 실측 비율
(번호 칸 160215 : 내용 칸 1810920)을 표 폭에 맞춰 스케일한다.

행높이 실측값은 `[382457, 268746, 496168, 268746]`이며, `rows`가 4를 넘으면 마지막 값을
반복한다.

셀 서식(실측):

| | 크기 | 굵게 | 정렬 | 수직 | 여백 |
|---|---|---|---|---|---|
| 번호 칸(0열) | 6.5pt | 예 | 가운데 | 중앙 | 상하좌우 18000 |
| 내용 칸(1열) | 7pt, 맑은 고딕 | 아니오 | 좌측 | 기본 | 좌우·상 9525, 하 0 |

### 기본 템플릿의 재편

`default_template.py`가 만드는 것이 바뀐다.

| 지금 | 앞으로 |
|---|---|
| 슬라이드 1장에 껍데기 도형 + 표 5개 + 텍스트박스 | **레이아웃 1개**에 껍데기 도형 + placeholder 3개, **슬라이드 0장** |
| 좌표를 코드가 전부 지정 | placeholder 좌표는 레이아웃이, 표·이미지는 `content_area`가 |

만드는 방법:

1. python-pptx 기본 템플릿의 `Title and Content` 레이아웃을 베이스로 잡는다
2. placeholder를 실측 자리로 옮긴다 — TITLE(idx 0) → `제목`, OBJECT(idx 1) → `화면ID`,
   DATE(idx 10) → `작성일`
3. 껍데기 도형(상단띠, 상단띠2, 구분선, 화면ID배경, 하단바, 문서제목, 쪽번호)을 임시
   슬라이드에 그린 뒤 XML을 레이아웃 `spTree`로 이식하고, 임시 슬라이드를 지운다
4. 슬라이드 0장으로 저장한다

껍데기 실측 좌표는 `docs/superpowers/plans/2026-08-05-default-template-parity.md`의 표를
그대로 쓴다. 슬라이드 크기는 9906000 × 6858000을 유지한다.

**저작권 원칙은 그대로다.** 제3자 저작권 문구는 넣지 않고, 원본에서 그 문구가 있던 자리
(`L0 T6738252 W2648744 H100027`)에는 표지에서 읽은 `문서제목`이 들어간다.

### screens.json 강등

`screens.json`은 SSOT가 아니라 **중간 산출물**이다. 파일 자체는 남긴다 — 세 가지 이득이
사람의 편집과 무관하게 유지되기 때문이다.

- `build.py`가 Excel을 모르므로 Excel 픽스처 없이 빌드 로직을 테스트할 수 있다
- 이미지 추출·변환이 느리므로, 매핑이나 템플릿만 고쳐 생성 단계를 반복할 때 캐시가 된다
- 결과가 이상할 때 추출이 틀렸는지 배치가 틀렸는지 갈라 볼 수 있다

없어지는 것은 덮어쓰기 보호뿐이다.

| 대상 | 조치 |
|---|---|
| `extract.py` | 항상 덮어쓴다. `diff_screens`·`screens.new.json` 경로 제거 |
| `tests/test_extract.py` | diff 관련 테스트 4개 제거 |
| `SKILL.md` | 원칙 문구 수정, 3단계의 diff 확인 절차 삭제 |
| `CLAUDE.md` | SSOT 규칙 문구 수정 |
| `build.py`의 openpyxl 금지 | **유지** — 테스트 격리와 캐시가 여기 걸려 있다 |

추출 결과가 어긋나면 `screens.json`을 손대지 않고 **매핑을 고쳐 재추출한다.** 원인이
매핑에 있기 때문이다.

### 테스트 픽스처의 재배치

`tests/fixtures.py`의 `make_template_pptx`는 지금 `build_default_template`이 만든
**예시 슬라이드**를 가져다 도형 이름만 실제 샘플처럼 바꿔 clone 모드 테스트에 쓴다.
기본 템플릿이 슬라이드 0장이 되면 이 픽스처가 성립하지 않는다.

새 방식: 기본 템플릿을 만든 뒤 **layout 모드의 슬라이드 생성 경로로 예시 슬라이드를 한 장
만들어** 그것을 clone용 템플릿으로 저장한다. 예시 텍스트와 도형 이름 변경은 지금처럼
픽스처가 담당한다.

`CLAUDE.md`의 "테스트 템플릿 픽스처는 `build_default_template`을 재사용한다" 규칙은
유효하되, 그 위에 슬라이드 한 장을 얹는 단계가 추가된다는 점을 문구에 반영한다.

## 오류 처리

경고 코드는 아홉 개 그대로다. 새 상황은 기존 코드에 흡수하거나 예외로 처리한다.

| 상황 | 처리 |
|---|---|
| `layout` 이름·인덱스를 못 찾음 | `ValueError` — 빌드가 성립하지 않으므로 중단 |
| `content_area`가 슬라이드를 벗어남 | `ValueError` |
| 같은 이름의 레이아웃이 여러 마스터에 있음 | 첫 번째를 쓰고 stderr 경고 |
| 지정한 idx의 placeholder가 레이아웃에 없음 | `shape-not-found` 경고 |
| 이미지 없음 / 상세 없음 | 기존 `no-image` / `no-detail` |
| 상세가 슬롯보다 많음 | 기존 `slide-split` / `slot-shortage` |

화면 단위 예외 격리는 그대로다. 한 화면이 실패해도 나머지는 완성하고, 실패는
`screen-failed` 경고로 남긴다.

## 테스트

| 대상 | 확인할 것 |
|---|---|
| layout 모드 빌드 | 기본 템플릿으로 화면 수만큼 슬라이드가 생기고 제목·화면ID가 채워진다 |
| placeholder 보충 상속 | DATE(idx 10)가 슬라이드에 생기고 값이 써진다 |
| 빈 placeholder 제거 | 값이 없는 placeholder가 결과물에 남지 않는다 |
| `content_area` 분할 | 이미지와 표가 영역 안에 들어가고 서로 겹치지 않는다 |
| 표 생성 | 개수·행수·열폭 비율·셀 서식이 명세대로다 |
| 레이아웃 탐색 | 이름·인덱스 모두 동작하고, 없는 이름은 `ValueError` |
| 기본 템플릿 | 레이아웃에 껍데기 도형과 placeholder 3개가 있고 슬라이드는 0장이다 |
| 제3자 저작권 부재 | 기본 템플릿 어디에도 해당 문구가 없다 |
| clone 모드 회귀 | 기존 테스트가 그대로 통과한다 |
| extract 덮어쓰기 | 재추출이 `screens.json`을 그냥 덮어쓴다 |

## 범위 밖

- 사용자가 준 템플릿의 레이아웃을 편집하지 않는다. 그 파일은 사용자 소유다
- 표지·목차를 만들지 않는다. 화면 페이지만 만든다
- 슬라이드 크기를 바꾸지 않는다. 템플릿 크기를 승계한다
- 상세 표 번호를 재부여하지 않는다. Excel 값이 스크린샷 뱃지와 대응한다
- 레이아웃에 표 placeholder를 심는 방식은 채택하지 않는다
